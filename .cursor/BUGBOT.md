# Bugbot レビュー方針（web-nfc-app）

コメント・指摘は**日本語**で書く。タイトルも日本語でよい。英語の API 名や識別子はそのままでよい。

詳細な実装規約は [frontend.mdc](rules/frontend.mdc) と [mvp.md](../mvp.md) を参照する。
フォーマットや import 順など Prettier / ESLint / commitlint が見るものは、それだけでは指摘しない。

---

## Blocking（要対応）

### 端末内完結・プライバシー

- NFC レコード内容・読取履歴・書込下書きを `fetch` / 外部 API / analytics / ログ収集へ送るコードを追加していないか
- Cookie に履歴・書込内容・NDEF ペイロードを入れていないか（Cookie はテーマ等の軽い設定のみ）

### Web NFC

- `NDEFReader` / Web NFC API を RSC・Server Action・Route Handler から触っていないか（Client Component のみ）
- スキャン／書込／消去の二重起動、abort 忘れ、失敗後に操作不能なまま戻らない経路がないか
- 非対応時（`NDEFReader` なし）の案内が消えていないか

### データが消えないか・壊れないか

意図しないデータ消失は blocking。次を重点的に見る。

- **履歴（localStorage）**: リロード・再マウント後も残るか。キー名・スキーマ変更で既存データが読めなくなっていないか（マイグレーションなしの破壊的変更）
- **100件上限**: 超過時は**古いものから**削除する。新しい件や無関係キーまで消していないか
- **書込下書き**: 編集中のレコードが意図せず空になる・上書きされる・保存されない経路がないか
- **テーマ Cookie**: 設定変更後に消える、RSC 初期表示と Client で食い違う、secure / path / max-age が壊れていないか
- **消去ダイアログ**: 確認なしでタグ消去が走らないか。キャンセル後に副作用が残らないか
- **parse / JSON**: 不正な localStorage・壊れたレコードでアプリ全体が白画面・全履歴消失にならないか（1件スキップ等）

### セキュリティ・Secure Context

- HTTPS / localhost 前提が崩れる変更（混在コンテンツで Web NFC が死ぬ等）
- 危険な動的実行（`eval` 等）や、ユーザー入力を HTML に生埋めして XSS になる経路

## Non-blocking（直した方がよい）

### アクセシビリティ

- 実装と一致しない ARIA（例: 実体が disclosure なのに `menu` / `radiogroup` / `haspopup`）を付けていないか
- 破壊的操作に確認がない、フォーカスがダイアログから漏れっぱなし、など実害があるもの

### アーキテクチャ

- `features/*` 同士の直接 import（共通は `components` / `lib`）
- `/components` に feature 専用のものを置きすぎていないか

### ブランド・アセット

- favicon（`app/icon.svg`）とサイト内 `BrandMark` / OGP で、同じマークを別構図のまま描いて見た目がずれていないか（枠のクリップ等）

### テスト

- 履歴上限・空入力・非対応ブラウザ・不正 JSON など境界の変更に、対応するテスト更新がない場合は指摘してよい（カバレッジ数値は求めない）

---

## 指摘しない・弱くする

- 未着手の Nice（i18n・PWA・AdSense 等）が「まだ無い」こと自体
- 変数名の好み、コメント量、自明なリネーム提案
- 「公式サンプルと違う」だけの UX 好み（ツール意図として妥当なら）

---

## コメントの書き方

- 何が壊れるか（データ消失・二重書込・非対応案内の欠落など）を先に書く
- 可能なら修正の方向を1〜2文で示す
- 誤検知の可能性がある場合は「要確認」と明記する
